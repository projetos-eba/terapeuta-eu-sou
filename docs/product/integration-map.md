# Mapa de Integração do Produto

Documento operacional para manter páginas, funções, banco e skills usando as mesmas fontes de verdade.

Atualizado em 2026-07-28.

## Rotas do terapeuta

- Namespace canônico executável: `/terapeuta/*`.
- Compatibilidade: `/basico/*`, `/pro/*` e `/plus/*` respondem com redirects
  temporários definidos em `next.config.mjs`.
- Catálogo e perfil público: `/terapeutas` e `/terapeutas/:slug`.
- Plano e capability são resolvidos por `src/lib/permissions.ts` e pela
  política do shell; nunca pela URL.
- Checkout, Billing Portal e Connect retornam para `/terapeuta/*`, sem URLs de
  plano fixadas nas Edge Functions.

## Regras Gerais

- Rotas canônicas: `src/lib/routes.ts`.
- Inventário de páginas: `docs/product/page-inventory.md`.
- Mapa navegacional: `docs/product/sitemap.md`.
- Contrato de rotas: `docs/product/routes-map.md`.
- Tokens e padrões visuais: `docs/design-system/design-system.md`.
- Toda página implementada ou refatorada deve ter skill local em `skills/`.
- Toda alteração de banco deve ter migration versionada em `supabase/migrations/`.
- Seeds/mocks devem ser idempotentes em `supabase/seed.sql` ou arquivo documentado.
- Fallback público não pode mascarar falha de produção. Dados demonstrativos
  exigem `TES_ENABLE_DEMO_DATA=true` no servidor fora de produção; zero
  resultados e 404 não ativam demo.
- Paciente usa `/app/encontros` como rota canônica. `/app/sessoes*` é legado
  compatível por redirect, não namespace para novas páginas.
- TES é online-only: serviços, agenda, reserva, perfil público, busca, Match,
  sessões e Zoom devem aceitar/expor apenas `online`. Campos técnicos legados de
  formato ficam como compatibilidade travada, não como escolha de produto.

## Pendências De Integração

- `/como-funciona`, `/reserva`, `/reserva/sucesso`, `/para-terapeutas/planos`, `/ajuda`, `/termos`, `/privacidade`, demais áreas logadas e admin fora de `/admin/terapias` ainda precisam ser implementadas ou auditadas quando entrarem no escopo.
- `/admin/matching` deve publicar versões completas de pesos, nunca edição parcial ao vivo.
- `/admin/terapias` edita `approach_label`, `approach_icon_key`, `visual_theme_key`, `hero_focal_point` e `therapy_faqs` sem gravar classes CSS/Tailwind no banco; o frontend mapeia `visual_theme_key` para tokens seguros.
- `/terapeuta/checkout` chama `stripe-create-subscription-checkout`, mas o plano pago so e ativado por `stripe-billing-webhook`. O catalogo Stripe precisa ser sincronizado por `npm run payments:catalog:sync` antes do uso real.
- Trocas de plano usam `stripe-change-therapist-subscription`: upgrade com prorrata imediata; downgrade agendado para o fim do periodo. Cancelamentos usam `stripe-cancel-therapist-subscription` com `cancel_at_period_end`.
- A2 concluiu as primitivas de Agenda, A5 concluiu os slots autoritativos e A6
  adicionou `session-booking-checkout` para orquestrar slot, hold, booking e
  `stripe-create-session-payment` por Edge Function autenticada.
- `/reserva` ainda precisa consumir `session-booking-checkout` quando a página
  pública de reserva entrar no escopo.
- Zoom depende de secrets nas Edge Functions, webhooks Video SDK configurados manualmente e homologação real controlada antes de produção.
